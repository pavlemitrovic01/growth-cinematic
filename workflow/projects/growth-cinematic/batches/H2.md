## Cilj

`Motion.tsx` dodaje `is-in` elementima pre nego što React završi hidrataciju tog dela stranice, pa React prijavi
neslaganje koje, po sopstvenoj poruci, **neće ispraviti**. Posle `H2` pokret dira DOM tek kad je bezbedno, upozorenja
nema, a sadržaj se otkriva isto — uključujući `data-wipe` naslove, koji su bez klase potpuno nevidljivi.

## Nalaz merenja pre plana (dev, 1440 × 900, po jedan prolaz)

```
  serverski HTML       `is-in` 0 na svih 10 ruta — server ne salje klasu
  DOM posle ucitavanja `is-in` na <h1 data-wipe> (i ponegde jos jedan div)
  upozorenje           7/10 ruta: /about /faq /contact /apply /truckers-lounge /privacy /terms
  bez upozorenja       / /how-it-works /for-carriers  → trka u vremenu, ne stalno stanje
  poruka               „A tree hydrated but some attributes … didn't match … This won't be patched up",
                       sporni atribut: className="is-in" na <h1 data-wipe> u <header class="sub-hero">
```

⚠️ **Zašto nije kozmetika:** element nosi klasu koju React ne zna da postoji. Ako se taj deo ikad ponovo iscrta,
klasa nestaje, a sadržaj iza `:not(.is-in)` se ponovo sakriva.

1. **Cekanje na `load`** (prva verzija): izmereno **23 upozorenja**, isto kao pre. Trag sa `/terms`: `load` 391 ms,

⚠️ **Oslanjanje na unutrasnjost React-a:** znak preuzimanja je kljuc `__reactFiber$…` na DOM elementu (isti trag koji
koristi React DevTools). Napisano je tako da sme da izostane — ako React promeni unutrasnjost, posle roka se sve odvija
kao pre `H2`, bez skrivenog sadrzaja. Resenje bez unutrasnjosti trazilo bi izmenu `app/globals.css`, koji **nije** u
EXPECTED-FILES.

⚠️ **Sto nije dirano:** vreme trajanja i izgled animacija, `data-reveal` ciscenje (`H1`), prelazak na CSS animacije
vezane za skrol.
